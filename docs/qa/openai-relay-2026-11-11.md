# 智谱浏览器连接失败：同源服务端转发

用户报告：同一 Ubuntu 服务器上的酒馆可使用 `https://open.bigmodel.cn/api/paas/v4` 与 `glm-5.3`，本项目提示网络/跨域连接失败。基线为 `8232be2`。

## 原因与修正

现有 OpenAI 兼容请求在浏览器直接发出，Ubuntu 上的其他后端客户端成功不能验证该路径。2026-11-11 对 `https://open.bigmodel.cn/api/paas/v4/chat/completions` 使用两个来源分别发送无密钥 OPTIONS，请求头声明 POST 以及 Authorization、Content-Type：均返回 200、`text/plain`，没有 Access-Control-Allow-Origin、Access-Control-Allow-Headers 或 Access-Control-Allow-Methods，不能满足浏览器跨域预检。

新增可选“通过本服务转发”：前端向同源 `/api/openai/chat/completions` 发请求，后端向管理员配置的固定 HTTPS 目标转发。JSON 连接测试和 SSE 生成共用这条通道。未开启的旧存档继续直连，不自动发起替代或重试请求。

管理员配置 `OPENAI_PROXY_BASE_URL` 与 `OPENAI_PROXY_ALLOWED_ORIGINS` 后重启；前端勾选转发。无需开启 Vertex 或提供 Google 凭据。`/readyz` 显示独立的 `openaiProxyEnabled`。完整操作见 [部署运维](../operations.md#openai-兼容接口服务端转发)。

## 边界

- 上游仅来自管理员配置；浏览器目标必须完全匹配，不接受重定向。允许来源、公开标记、请求格式及认证头均经过检查。上游不能来自任意请求参数。
- 认证密钥来自当前浏览器的每次请求，会经过当前部署服务器；应用不记录或持久化密钥。组织认证入口应保护新路由，公开标记不是登录认证。
- 共用限流、请求大小、超时和停机取消。返回内容最多 8 MiB；上游错误与日志脱敏。流中断会发送可识别的错误帧，前端不提交不完整正文。
- 对本项目文本 Chat Completions 有效，不是任意工具、文件上传、其他协议的通用代理。允许的自定义头见运维文档。

## 证据

- 新增测试在实现前确认失败：路由缺失、没有配置字段、前端仍直连。实现后定向通过。
- `backend/openai-relay.test.js`：9 项真实本地 HTTP 测试，覆盖默认关闭、精确来源、目标匹配、认证头过滤、请求限制、独立于 Vertex、JSON、SSE、客户端取消、超时、脱敏、重定向、8 MiB 上限和排空。含实际前端 AIProviderService 经真实 HTTP 后端完成连接测试与流式生成的集成用例；上游使用受控响应，不调用付费模型。
- 前端覆盖转发选择的测试/保存/重开、旧备份兼容、布尔字段校验、无自动直连回退及配置错误提示。
- `npm run check`：退出码 0，前端 192、后端 30、交付/扫描 6，合计 **228 项通过**；类型检查和构建通过。
- 实际 Node 生产入口 HTTP smoke：默认配置及开启固定智谱转发配置均通过，AI Vertex 保持关闭；检查健康、就绪、页面、3 项资源与路由边界，结束后停止临时进程。
- `git diff --check`：通过。

独立复核确认一处重要停机竞态：请求通过入口检查后，若上传正文期间开始停机，正文完成后仍可能发起新的上游请求。已用真实分段上传先复现 HTTP 200 与额外调用，再于解析正文后重新检查排空状态，回归验证返回 503 且上游调用为零。没有其他 Critical 或 Important 问题。

没有使用用户密钥，也没有真实模型生成验收；用户服务器到智谱的网络、账号权限、模型输出以及真实浏览器交互需部署后验证。已知此前用户浏览器/原生自动化连接不可用，本轮不把网络探测或模拟上游测试描述为真实端到端成功。

# GLM-5.3 思考预算与请求时限适配

基线 `f8e3d9f`。用户启用转发后，错误从浏览器 CORS 变为收到响应但没有有效正文。已确认程序把所有 OpenAI 兼容连接测试限制为 32 输出 token、20 秒。根据 [智谱官方说明](https://docs.bigmodel.cn/cn/guide/models/text/glm-5.3)，GLM-5.3 始终启用思考、默认 `reasoning_effort=max`，不支持禁用思考。

固定的微小预算不适合此模型。用户没有提供原始响应元数据，因此“此次预算全部用于思考、finish_reason=length”仍是有依据的推断，不当作实测结论。

修正：精确识别 `glm-5.3`（也接受带命名空间的同名模型），连接测试使用 low 强度、2048 输出 token、60 秒时限，保留单次请求与取消能力。不给其他模型添加思考参数，不自动重试，不改变作者保存的创作输出 token 预算。后端转发允许并校验 low/high/max 枚举，不放开任意额外字段。

2026-11-12 用户进一步报告正常创作触发固定 90 秒超时。在模型设置中增加可保存的思考强度和 30–600 秒客户端每次等待上限，GLM 默认 low/300 秒，其他兼容模型保持 90 秒。共享请求策略供服务、设置页和当前生效面板使用。Compose 显式透传 API_TIMEOUT_MS，默认后端 120000 不变；部署需设置 300000 与前端匹配，外部网关也需相容。GLM 断点签名包含思考强度，修改强度拒绝恢复旧断点，单纯延长等待时间可以继续。

仅返回 reasoning_content 或达到输出限制而无 content 时，仍判定失败，显示静态可操作提示；不泄露思考原文、不将其作为故事正文。忽略流式参数而返回 JSON 的供应商也经过同样检查。

回归：先复现 GLM 测试参数错误、空正文诊断错误及后端拒绝新增参数，再实现修正；测试覆盖普通模型仍用原预算、GLM 不禁用思考、正常生成保留输出上限、空正文不误报成功、错误不回显秘密、非法强度/时限被拒绝、设置保存、备份验证、断点兼容，以及实际前端服务经真实本地 HTTP 转发的参数透传。一次并行验证发现旧超时测试依赖 5ms/30ms 竞速，改为在验证超时后才释放响应正文，保留超时与迟到响应语义。

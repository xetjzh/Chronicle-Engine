# 部署、运维与交付基础

用户要求继续优化开源与企业管理能力，并明确优先部署、运维和交付规范。沿用现有 React、Vite、Node 工作区与浏览器本地存档，不提交、不发布，在当前工作目录增量实施。

## 目标与方案

交付可由干净检出构建、无云凭证启动、具备运行状态与回滚说明的应用。选择 Node 单容器同时提供构建后的前端和现有可选 Vertex 代理：相比另加 Nginx 容器，入口、镜像和健康检查更少；相比只补文档，可以实际验证交付链。保留前后端开发模式。

- 默认关闭 AI 代理；显式开启时验证项目、区域、公开 shim 标记和来源配置。静态标记不是认证，公开部署须通过组织认证网关保护 HTTP 与 WebSocket；不引入临时账号系统。
- `GET /healthz` 表示进程存活；`GET /readyz` 表示配置完成且未排空，不调用付费 AI、不承诺 ADC 或供应商可用。
- `SERVE_FRONTEND=true` 从 `frontend/dist` 提供静态文件。入口 HTML 不缓存，带哈希资源长期缓存；API 错误不回退为 HTML。
- 容器使用非 root 用户、锁文件安装、排除本地凭证、终止信号与健康检查。Compose 默认仅绑定宿主机回环地址，可直接运行无 AI 模式。
- 后端消除未声明依赖，修复异常输入、云端超时、敏感日志与关闭流程的已确认缺陷；保留已有上游白名单和请求体策略。
- 统一 `npm run check`，覆盖前后端测试、类型与构建；CI 验证 Node 22.18+ / 24、容器构建、健康检查与入口静态资源。
- 文档提供环境变量、启动、TLS/认证入口、日志、备份、升级、回滚、事故排查与贡献流程；应用内指南对应真实仓库文件。

## 边界与验收

不迁移浏览器存档，不声称已有中心数据库、多人协作、RBAC、审计留存或合规认证。不擅自选择项目许可证或指定维护者。已有 Google 版权和 SPDX 标记保留。

验收：自动化测试、类型检查、构建与本地真实 HTTP 启动检查通过；坏配置尽早报错；畸形 HTTP/WS 请求不崩溃；健康检查不泄漏配置；停机有时限。Docker 不在当前机器中，镜像运行验收交由新增 CI，最终说明此限制。

# OpenAI 兼容服务端转发

用户在同一服务器的酒馆能连接智谱，本项目浏览器直连失败。2026-11-11 对智谱 `/api/paas/v4/chat/completions` 携带 `Origin: http://localhost:18080` 的 OPTIONS 实测返回 200，但没有 Access-Control-Allow-Origin/Headers/Methods，不能满足浏览器预检。

采用显式开启的同源服务端转发：服务器配置唯一 HTTPS 上游基址及精确网页来源；浏览器选择转发，仍使用自己的连接密钥。服务端逐请求使用密钥，不落盘、不记录。校验目标与管理员配置一致、限制请求头与请求格式，拒绝重定向，复用限流、超时与停机取消。JSON 和 SSE 都可用，不自动降级重试付费请求。

- [x] 前端选择转发，测试和生成共用传输；错误提示明确；旧存档默认直连，新增字段校验。
- [x] Compose/Vite/运维示例；完整检查、实际 HTTP 验证与代码复核。提交和推送沿用既有授权，最终结果以 Git 记录为准。

不要求用户提供密钥，不进行付费推理。不将浏览器 CORS 当作密钥错误，不将本地网络探测当作用户服务器或真实凭据验收。

独立复核发现的停机上传竞态已先失败再通过验证修正。最终检查包含 228 项测试；默认与转发启用配置的实际 HTTP smoke 通过。结果见 [验证记录](../../qa/openai-relay-2026-11-11.md)。
